# AICodingProjectAssistance（AICoding项目辅助、管理系统） · 操作手册

> AI coding 开发项目全流程辅助、项目管理平台：需求分析 → 项目计划 → 架构设计 → 任务管理 → 工时登记 → 测试管理 → 交付文档 → 运营管理，配套知识库（RAG）、Wiki 知识库（LLM 编译）、模型管理与 **MCP 服务**（供 Trae / Claude Code / Cursor 等编程 Agent 接入协同）。
>
> 部署与安装细节见 [README.md](../README.md)，本手册聚焦**页面操作**与 **MCP 使用**。

---

## 一、系统简介与角色

| 角色 | 典型用途 |
|------|---------|
| admin 管理员 | 全部功能，用户/权限/模型管理 |
| manager 项目经理 | 需求确认、计划生成、派单、成员管理 |
| developer 开发 | 领任务、开发、登记工时 |
| tester 测试 | 用例、测试执行、提缺陷 |
| guest 访客 | 只读浏览 |

权限采用**白名单制**：管理员在「权限组管理」中把资源码（菜单/按钮）配置到权限组，再把用户加入权限组；未配置过的资源码默认全员放行，配置后按组授权。admin 始终全权。

账号无注册入口，由管理员在「用户管理」创建或 `createsuperuser` 生成。

## 二、全局操作

### 2.1 登录
- 输入用户名、密码、**图形验证码**（点击图片可刷新）。
- 登录参数经 RSA 公钥加密后传输；登录失败会自动刷新验证码。

### 2.2 全局项目选择器（右上角）
- 位于页面**右上角**（用户菜单左侧），全系统共享：选一次，所有菜单生效；刷新页面后仍保持（本地持久化）。
- 切换项目后，当前菜单的数据自动刷新。
- 在「需求分析」页新建/删除项目后，选择器列表自动同步。
- 各页面内的大量操作（需求、计划、任务、缺陷等）都以当前选中的项目为准，**先选项目，再干活**。

### 2.3 项目生命周期
```
需求分析 → 项目计划 → 架构设计 → 开发实施 → 项目交付 → 项目运营
```
项目的阶段状态可在「需求分析」页（项目列表）变更，各阶段对应页面会校验前置条件（如：生成计划前需求须已确认）。

## 三、页面功能手册

### 3.1 首页（Dashboard）
个人工作台：我的待办任务、本周工时等统计概览。登录后的默认落地页。

### 3.2 项目概览
以「项目冒险之旅」形式按阶段（需求 → 计划 → 架构 → 开发 → 交付 → 运营）展示项目全景：每个阶段的产出物与进度。适合项目经理快速掌握项目状态。

### 3.3 需求分析（项目管理 → 需求分析）
**两块内容：项目列表 + 需求文档管理。**

- 项目列表：新建/删除项目、变更项目状态、邀请/移除成员、进入项目详情。
- 需求文档：上传 docx/pdf/md 需求文档 → AI **完整度检测**（评分、缺失项提示）→ 人工确认入库。
- 需求确认后项目进入「项目计划」阶段；需求正文可作为 Wiki 编译与测试用例生成的源。

### 3.4 原型图/UI图管理
- 上传原型图 / UI图 / 业务流程图，命名建议 `端-模块-功能`（如 `Web-登录-验证码`），项目内名称唯一。
- 任务可关联这些图（`ui_images`）；MCP 侧 agent 可按名称检索并**下载图片字节**（base64）辅助开发。

### 3.5 项目计划
- 选择参与成员并分配**开发权重**（和约为 1）→ AI 生成项目计划（markdown）→ 可编辑/重新生成 → **生成任务**（按权重拆分并指派）。
- 生成任务后项目进入「架构设计」阶段。
- 也支持把 agent 侧已写好的计划直接入库（见 MCP `project_plan_create`）。

### 3.6 任务管理
- 任务列表：按状态（待执行/执行中/已完成/阻塞）、负责人、关键词、日期过滤。
- 新增/编辑任务：标题、描述、模块、难度、预估工期（人日）、负责人、计划起止、前置依赖、**关联 UI 图**。
- 操作：AI 生成任务、任务/工时导出 Excel、知识入库。

### 3.7 架构设计
- 选择前端/后端技术栈、框架底座（Ruoyi-Vue-Plus / Smart-Admin / 无）、数据库类型（MySQL / PostgreSQL）→ **两步流式生成**：架构概设文档 + 数据库设计 SQL。
- 支持多版本保存、AI 对话追问（可参考需求文档）、专家评审角色对话。
- 确认后的架构文档与 SQL 可「知识入库」，供知识库检索。

### 3.8 缺陷管理
- 缺陷 CRUD：标题、描述、模块、严重程度（低/中/高/严重）、状态流转（待处理 → 处理中 → 已修复 → 待复测 → 已关闭）、处理人、关联开发任务。
- 支持缺陷截图上传；顶部统计卡片（总数/未关闭/按状态分布）。
- 测试任务失败可一键转缺陷（见 3.13 / MCP `bug_from_test_task`）。

### 3.9 运营管理
- **运营记录**：迭代需求 / 优化需求 / 业务变更 / 用户反馈，状态流（评估 → 受理 → 排期 → 已上线 → 关闭）、优先级、提出人。
- **运营指标**：按月登记续期/续费、满意度、活跃用户等数值指标。
- 统计视图 + 知识入库。

### 3.10 工时登记（协同）
- 三个页签：**工时登记**（提交/查询/修改，关联任务）、**统计**（按人/按项目汇总）、**周总结**（AI 生成个人/项目周报，可删除）。
- 支持按日期范围筛选与 Excel 导出。

### 3.11 工作群
- 项目维度的群聊：项目创建时可自动建群，成员即项目成员。
- 用途：人与 agent 的**协同消息中心**——agent 开发完成/测试完成会在群里汇报（MCP `workgroup_message_send`），人可回复指派。
- 管理员可解散群；被解散的群仍可查阅历史。

### 3.12 知识库（传统 RAG）
- 知识条目增删 + **语义检索** + **知识问答**（流式、多会话）。
- 原理：文档/文本 → 切片 → Embedding → Chroma 向量库（按项目隔离）。
- 强项：**原文精确性**——问"需求原文第几条写了什么、精确数值"用这里。

### 3.13 Wiki 知识库（LLM 编译）
- 把源文档（需求/架构/项目计划/交付文档）由 LLM **编译为结构化知识页**：固定页面类型（总览/业务模块/实体/数据表/接口/时间线/综合分析）、页面双链、来源引用。
- 源文档更新后可**覆盖式重编译**；编译为异步任务，可查进度。
- **Wiki 问答**：Agentic 多轮检索（先命中页面，不足时顺双链补充关联页），支持会话记忆。
- 强项：**全局理解**——问"怎么设计的/为什么这么定/各模块怎么关联"用这里。
- 与 3.12 知识库相互独立，按问题类型选用。

### 3.14 测试管理
- 三个页签：**用例**（CRUD、AI 按需求/任务生成用例、导出）、**任务**（派单：用例指派执行人；执行：通过/失败/阻塞；改派）、**统计**（通过率、状态/优先级分布）。
- 失败/阻塞的测试任务可**一键转缺陷**。
- 可生成测试报告并导出。

### 3.15 交付文档
- 管理项目交付物（架构设计文档、测试文档、部署文档、其它），4 类固定类型；可按标题/类型/内容关键词搜索。
- 两种提交方式：**上传文件**（附件）或**粘贴 Markdown 内容**；删除限管理员/项目经理或文档创建者本人。
- 交付文档也是 Wiki 编译的源类型之一（`source_type=delivery`）。

### 3.16 模型管理
- 配置 **LLM**：Base URL / API Key / 模型名（OpenAI 兼容协议，如 DeepSeek、火山方舟），保存后「测试 LLM 连接」。
- 配置 **Embedding**：local（bge-small-zh 本地模型）或 remote（远程 embedding API），保存后测试。
- 页面配置优先于环境变量（`LLM_API_KEY` 等环境变量兜底）。

### 3.17 用户管理（管理员）
- 用户增删改、角色调整、启用/禁用、重置密码。
- **MCP Token**：每个用户有专属 Token（`mcp-` 前缀），点击「查看Token」复制；「重新生成Token」使旧 Token 失效。该 Token 用于 MCP 接入时**标识操作者身份**（详见第五章）。

### 3.18 日志管理
- 查看 Embedding / AI 调用日志（向量入库、检索调用记录），排查向量库与模型调用问题。

### 3.19 权限组管理（管理员）
- 新建/删除权限组（角色），树形勾选**资源码**：菜单（menu:*）与按钮（btn:*）。
- 用户在「用户管理」中分配权限分组；分组勾选过的码才对该组用户可见/可用。

## 四、MCP 功能介绍

### 4.1 MCP 是什么、架构是什么

MCP（Model Context Protocol）是 AI Agent 调用外部工具的标准协议。本平台的 MCP 服务端让 **Trae / Claude Code / Cursor 等编程 Agent 直接读写平台数据**，实现"人在平台上管，Agent 在旁边干"：

```
┌─────────────┐   MCP(stdio/JSON-RPC)   ┌──────────────────┐   HTTP+Token   ┌──────────────┐
│ 编程 Agent    │ ◄──────────────────────► │ mcp_server.py     │ ─────────────► │ 平台后端 API   │
│ Trae/CC/Cursor│    tools/list tools/call │ （本仓库提供）      │                │ Django        │
└─────────────┘                          └──────────────────┘                └──────────────┘
```

- 服务端为**纯 stdio 实现**（`JSON-RPC 2.0`，仅依赖 `httpx`），客户端以子进程方式拉起 `python mcp_server.py`。
- 所有工具按**项目**维度工作：默认项目在配置文件指定，单次调用可用 `project_id` 覆盖。
- 身份与权限：用**哪个用户的 MCP Token**，就按哪个用户身份操作（须为项目成员或管理员）；写操作权限与平台页面完全一致。

### 4.2 服务端位置与工具集

| 位置 | 用途 | 工具数 | 说明 |
|------|------|-------|------|
| `mcp-client/mcp_server.py` | 本地开发接入（本机 `127.0.0.1:8000`） | 55 | 含 `delivery_doc_upload`（上传交付文档）、`test_report`（测试报告） |

本仓库提供**一份**服务端（上表），工具集已含交付与测试报告工具；若某平台不需要这些工具，从文件内 `TOOLS` 列表中移除对应项即可。

### 4.3 服务端配置

配置来源优先级：**环境变量 > 同目录 `mcp_server_config.json` > 默认值**。

| 配置项 | 说明 | 默认 |
|--------|------|------|
| `PLATFORM_API_URL` | 平台后端地址 | `http://127.0.0.1:8000` |
| `PLATFORM_API_TOKEN` | 调用者身份 Token：推荐用「用户管理」里查到的**用户 MCP Token**（`mcp-` 开头）；也可用后端环境变量 `PLATFORM_SERVICE_TOKEN` 所设的**服务令牌**（自动映射为管理员账号 mcp，仅限可信环境；生产部署必须自定义，不能用默认值） | `local-mcp-service-token`（仅 DEBUG=1 开发环境可用） |
| `PLATFORM_PROJECT_ID` | 默认项目 id | `1` |

配置方法：把同目录已入库的模板 `mcp_server_config.example.json` 复制为 `mcp_server_config.json` 再填值（真实配置文件已 gitignore，请勿提交真实 Token）：

```bash
cp mcp_server_config.example.json mcp_server_config.json
```

依赖安装：`pip install httpx`。

### 4.5 使用约定（给 Agent 的注意事项）

1. **长文分页**：需求正文 / 计划正文 / 架构正文 / Wiki 页面等正文类工具按约 1000 字符分页（`page_size` 可调，最大 20000），返回含 `total_pages/has_more`——请循环 `page=1..total_pages` 拼接，不要期望一次取全。
2. **概要 + 正文两段式**：列表类工具返回概要（不含正文），要先查列表拿 id，再调对应 `*_content_query` 读正文。
3. **身份即权限**：Token 决定你能操作哪些项目；403 通常是"不是该项目成员"。
4. **中文保护**：服务端内置 Windows 管道中文损坏修复；如仍见乱码请检查客户端编码。
5. **群消息礼仪**：开发完成应在工作群发总结（如"已完成 xx 模块，已生成用例与任务，请测试同学开始测试"）。

## 五、MCP 与其它 Agent 配合使用

### 5.1 通用接入配置（stdio）

所有支持 MCP 的客户端都用同一段 JSON（**路径按实际项目位置修改**）：

```json
{
  "mcpServers": {
    "ai-platform": {
      "command": "python",
      "args": ["./mcp-client/mcp_server.py"]
    }
  }
}
```

- 服务端固定为 `mcp-client/mcp_server.py`，配置文件为同目录 `mcp-client/mcp_server_config.json`。
- 连**远程部署的平台**：把配置里的 `PLATFORM_API_URL` 填成目标服务器地址即可，无需换文件；若需与本地实例并存，复制一份目录、改好配置后分别注册即可。
- 若 `python` 不在 PATH，把 `command` 换成 Python 路径。

### 5.2 Trae 配置

1. 打开 Trae → 右上角「设置」→ **MCP**（或左侧 AI 面板 → MCP 标签）。
2. 点击 **添加 MCP Server** → 选择「手动添加 / JSON 编辑」。
3. 粘贴上面 5.1 的 JSON（Trae 全局配置文件位于 `~/.trae-cn/mcp.json`，项目级跟随工作区）。
4. 保存后确认服务显示**绿色可用**状态，工具列表能看到 `knowledge_search` 等即成功。
5. 对话中即可直接调用，例如：「帮我查一下平台里项目 1 的所有任务」。

### 5.3 Claude Code 配置

方式 A（命令行，推荐）：

```bash
# 项目级（仅当前项目可用，写入 .mcp.json）
claude mcp add ai-platform --scope project -- python ./mcp-client/mcp_server.py

# 用户级（所有项目可用）
claude mcp add ai-platform --scope user -- python ./mcp-client/mcp_server.py
```

方式 B（手写 `.mcp.json`，放在项目根目录）：

```json
{
  "mcpServers": {
    "ai-platform": {
      "command": "python",
      "args": ["./mcp-client/mcp_server.py"]
    }
  }
}
```

启动 `claude` 后用 `/mcp` 命令查看连接状态与工具列表。

### 5.4 Cursor / VS Code 配置

- **Cursor**：设置 → MCP → Add Server，或编辑 `~/.cursor/mcp.json`，粘贴 5.1 的 JSON。
- **VS Code（Copilot Chat）**：项目根建 `.vscode/mcp.json`，粘贴同样的 `mcpServers` 结构，命令面板执行 `MCP: List Servers` 确认已启动。

### 5.5 典型协作场景（Agent 工作流）

**场景 A：PM Agent 生成项目计划**

```
requirement_query → requirement_content_query(分页读全文)
→（Agent 内部生成计划 markdown）
→ project_plan_create(requirement_id, members[{user_id,weight}], plan_content)
→ project_plan_tasks_submit(plan_id, tasks[...])   # 批量导入任务并指派
```

**场景 B：开发 Agent 领任务开发**

```
task_query(user_id=自己) → 挑选 pending 任务
→ prototype_image_query(name=模块名) → prototype_image_download(image_id)  # 看图开发
→ （Agent 写代码实现）
→ task_update(task_id, status=executing→done)
→ worklog_submit(hours, description, task_ids)
→ workgroup_message_send("已完成xx模块，请测试同学开始测试")
```

**场景 C：测试 Agent 测试闭环**

```
test_case_generate(source=task, task_id=xx) → 人工/自动确认用例
→ test_task_dispatch(test_case_id, assignee_id) → 执行
→ 通过：test_task_update(status=passed)
→ 失败：test_task_update(status=failed) → bug_from_test_task(test_task_id)
→ test_statistics 汇报进度
```

**场景 D：架构 Agent 出设计**

```
requirement_content_query(读需求) → wiki_page_query(看已有知识)
→（Agent 生成架构文档 + SQL）
→ architecture_upload / architecture_update + sql_update
→ wiki_compile_source(source_type=architecture)   # 编译进 Wiki 知识网络
```

**场景 E：知识沉淀与问答**

```
wiki_page_add(title="模块-勋章系统", content=..., links=["模块-用户体系"])  # 双链关联
knowledge_add(text=...)                                            # 原文级知识
knowledge_search / wiki_page_content_query                          # 后续项目随时检索
```

### 5.6 多 Agent 协同建议

- 给每个 Agent 使用**各自用户的 MCP Token**，工时/任务/群消息能区分是谁干的。
- 以**工作群为消息总线**：开发 agent 完成即 `workgroup_message_send` 汇报，测试 agent 轮询 `workgroup_message_query` 认领，项目经理在群里裁决。
- 同一任务避免两个 agent 并发修改；用 `task_update` 的状态字段（pending/executing/done/blocked）做简单锁。

## 六、常见问题（MCP 相关）

| 问题 | 排查 |
|------|------|
| 客户端里 MCP 服务启动失败 / transport closed | 确认已 `pip install httpx`；`command` 用 Python 绝对路径；查看客户端日志中的 stderr |
| 工具调用返回 401 | `PLATFORM_API_TOKEN` 错误或已重新生成；到「用户管理」重新复制 Token |
| 工具调用返回 403 | 该 Token 用户不是目标项目成员（管理员除外），换成员 Token 或调整项目成员 |
| 中文入库变乱码 | 服务端已内置修复；若仍出现，确认客户端以 UTF-8 传参（Windows 控制台执行 `chcp 65001`） |
| 工具列表为空 | 客户端未完成 initialize 握手，重启客户端/MCP 服务再试 |
| 返回正文被截断 | 正文类工具按分页返回，按 `total_pages` 循环 `page` 拼接（见 4.5） |
| 连不上远程平台 | 检查 `mcp-client/mcp_server_config.json` 的 `PLATFORM_API_URL` 是否可达、防火墙/安全组是否放行 |

平台侧安装、模型配置、Docker 部署等见 [README.md](../README.md)。
